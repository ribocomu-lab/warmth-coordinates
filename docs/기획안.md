# 온도의 좌표 기획안

> 새벽에 온 친구의 메시지에 답하다 보면, 내가 듣고 싶었던 말이 드러나는 대화형 웹 콘텐츠

- **가제**: 온도의 좌표 (원안: 내가 건넨 온도의 좌표)
- **상태**: 기획 초안 (2026-11-05)
- **한 줄 카피**: "그 말, 사실 네가 듣고 싶었던 거 아니야?"

---

## 1. 핵심 아이디어

보통의 심리 테스트는 "나는 어떤 사람인가요?"라고 묻는다. 이 사이트는 묻지 않는다. 힘들어하는 친구에게 답장을 보내게 하고, 그 답장을 모아 **내가 쓴 말을 그대로 나에게 돌려준다.**

기존 테스트와 다른 점은 세 가지다.

| | 일반 문항형 테스트 | 온도의 좌표 |
|---|---|---|
| 응답 방식 | 5점 척도, 보기 선택 | 친구에게 메시지 보내기 (선택, 수정, 직접 쓰기) |
| 수집하는 것 | 점수 | 위로 유형 + 내가 쓴 문장 + 대화 습관 |
| 결과의 절정 | 유형 설명 | 내가 보낸 말풍선이 나에게 되돌아오는 장면 |

### 대화의 숨은 장치 두 개

1. **"근데 넌 요즘 어때?"**: 내내 위로하던 사용자에게 친구가 되묻는다. 남은 잘 챙기면서 자기 얘기는 넘기는 성향이 이 한 턴에서 드러난다.
2. **말풍선 반전**: 결과 화면에서 오른쪽에 있던 내 말풍선이 왼쪽으로 넘어와 나에게 도착한다.
   > "오늘 이 말을 스스로에게 소리 내어 읽어주세요."

---

## 2. 타깃과 목표

- **타깃**: 20~30대. 주변에서 "잘 들어주는 사람"이라는 말을 듣지만 정작 자기 얘기는 잘 못 꺼내는 사람
- **경험 목표**: 3~4분 안에 끝나고, 마지막에 "어, 이거 나네" 하고 조용히 찔리는 순간이 있을 것
- **확산 목표**: 결과 카드 공유, "너는 친구한테 뭐라고 해?" 비교

### 초기 지표 (출시 후 조정할 가설값)

| 지표 | 목표 | 의미 |
|---|---|---|
| 대화 완료율 | 70% 이상 | 대화 몰입 |
| 직접 쓰기 1회 이상 | 30% 이상 | 대화처럼 느꼈는지 |
| 결과 "맞는 것 같아요" 응답 | 60% 이상 | 해석의 납득도 |
| 카드 저장·공유율 | 15% 이상 | 확산력 |

## 3. 사용자 흐름

```text
[랜딩] → [친구 이름 정하기] → [대화 7턴] → [말풍선 반전] → [결과] → [카드 저장·공유]
 10초        10초             2~3분          10초          30초+
```

### 3-1. 랜딩

- 메시지 알림처럼 보이는 첫 화면: 잠긴 휴대폰 위로 **"자...?"** 알림 하나
- 버튼: **[답장하기]**
- 하단 안내: "가상의 친구와 나누는 대화예요. 의학적 진단이 아닌 자기 이해 콘텐츠이고, 쓴 내용은 이 기기 밖으로 나가지 않아요."

### 3-2. 친구 이름 정하기

"힘들 때 먼저 떠오르는 친구가 있나요? 그 친구를 뭐라고 부르세요?"

- 직접 입력 또는 건너뛰기 (건너뛰면 기본 이름 "지우")
- 실제 친구를 떠올리게 하면 대답이 진짜 말투에 가까워진다. 이름은 기기 안에서만 쓰고 공유 카드에는 넣지 않는다.

### 3-3. 대화

메시지 앱 형태의 화면에서 진행한다. 조작 흐름은 아래와 같다.

```text
┌──────────────────────────┐
│ ‹  지우            02:13 │
├──────────────────────────┤
│ ┌───────────────────┐    │
│ │ 나 요즘 진짜 아무것도   │    │
│ │ 못 하겠어           │    │
│ └───────────────────┘    │
│ ┌───────────────┐        │
│ │ 집 오면 그냥 누워 있어 │        │
│ └───────────────┘        │
│                          │
│  [너 그동안 진짜 잘 버텼어]    │  ← 보기를 누르면
│  [이번 주말은 그냥 푹 쉬어] │     입력창에 채워짐
│  [지금 전화할까? 말 안 해도 돼] │
│                          │
│ ┌──────────────────┐ ┌─┐ │
│ │ 직접 쓰기...         │ │↑│ │  ← 고쳐서 보낼 수 있음
│ └──────────────────┘ └─┘ │
└──────────────────────────┘
```

**핵심 인터랙션: 고르면 바로 끝나지 않고, 입력창에 채워진다.** 사용자는 내용을 그대로 보내거나 자기 말투로 고친 뒤 전송 버튼을 누른다. 보기만 누르는 사람도 "내가 보냈다"는 감각을 갖게 되고, 고친 내용 자체가 말투 데이터가 된다.

그 밖의 연출:

- 입력 중 표시(...)와 읽음 표시. 친구의 답장 대기 시간은 최대 1.5초로 제한
- 사용자가 보낸 유형에 따라 친구의 다음 반응이 살짝 달라짐
- 진행률 막대 대신 화면 상단 시각이 02:13 → 02:41로 흘러감
- 대기 연출을 건너뛰는 탭 동작 제공, `prefers-reduced-motion`이면 애니메이션 생략

### 3-4. 말풍선 반전

대화가 끝나면 화면이 어두워지고 문구가 뜬다.

> "지우는 이제 잠들었어요.
> 그런데 오늘 건넨 말들, 혹시 다른 사람도 듣고 싶어 하지 않았을까요?"

오른쪽의 내 말풍선들이 하나씩 왼쪽으로 넘어오고, 대화 상대 이름이 **"지우" → "나"** 로 바뀐다.

### 3-5. 결과

위에서 아래로 한 번에 하나씩 읽히도록 구성한다.

1. **오늘 건넨 말 중 한 문장**: 내가 직접 쓴 문장을 우선해서 크게 보여줌
2. **내가 듣고 싶었던 말과 유형**: 4장 참고
3. **이게 맞나요?**: [맞는 것 같아요] / [다른 말에 더 끌려요] (누르면 6개 문장 중 다시 고를 수 있고, 카드도 그 문장으로 바뀜)
4. **온도의 좌표**: 건네는 방식과 받는 힘의 4분면 위 내 위치
5. **대화 습관 3줄**: "보내기 전에 말을 4번 고쳤어요", "먼저 물어본 횟수 2번"
6. **오늘의 문장 카드**: 저장, 공유
7. **고지와 도움 안내**: 7장 참고

## 4. 유형 설계

원안의 4개 유형(인정, 안식, 수용, 동행)에 실제 대화에서 자주 나오는 **공감형, 해결형**을 더해 6개로 구성한다. 이 둘이 없으면 직접 쓴 답장 상당수가 어느 유형에도 들어가지 않는다.

| 위로 유형 | 친구에게 건네는 말 | 숨은 내 안의 아이 | 내가 듣고 싶은 말 |
|---|---|---|---|
| 인정형 | "너 그동안 진짜 잘 버텼어" | 칭찬 스티커를 모으는 아이 | "넌 이미 충분히 잘했어" |
| 안식형 | "아무것도 하지 말고 쉬어" | 불 끄는 걸 허락받고 싶은 아이 | "오늘은 여기까지만 해도 돼" |
| 수용형 | "그런 너여도 괜찮아" | 착한 아이를 연기하는 아이 | "아무것도 안 해도 네가 좋아" |
| 동행형 | "내가 옆에 있을게" | 창가에서 기다리는 아이 | "나 여기 있어. 어디 안 가" |
| 공감형 | "진짜 힘들었겠다" | 말 안 해도 알아주길 바라는 아이 | "그동안 얼마나 힘들었어" |
| 해결형 | "일단 이것부터 해보자" | 혼자 일찍 어른이 된 아이 | "이제 네가 다 해결 안 해도 돼" |

해결형만 거울상이 아니라 뒤집어 해석한다. 해결책을 건네는 사람에게 필요한 말은 또 다른 해결책이 아니라 내려놓아도 된다는 말이라고 본다.

### 온도의 좌표 (4분면)

- **가로축, 건네는 방식**: 곁에 머무는 말(공감, 수용, 동행) ↔ 일으켜 주는 말(인정, 안식, 해결)
- **세로축, 받는 힘**: "근데 넌 요즘 어때?"에 대한 답으로 결정. 자기 얘기를 꺼내거나(열림) 잘 모르겠다고 머문 답(모름)은 위쪽, 괜찮다고 하거나(닫힘) 화제를 돌린 답(돌림)은 아래쪽

| | 곁에 머무는 말 | 일으켜 주는 말 |
|---|---|---|
| **받는 힘이 열림** | 마주 앉는 사람 | 함께 걷는 사람 |
| **받는 힘이 닫힘** | 혼자 불 켜두는 사람 | 앞에서 끌어주는 사람 |

온도를 "36.2도"처럼 숫자로 표시하지 않는다. 근거 없는 수치가 측정값처럼 보이기 때문이다. '온도'는 콘셉트와 색상 표현으로만 쓴다.

## 5. 대화 스크립트 초안

- 친구는 고민을 세 가지 꺼내고, 중간에 위로를 한 번 튕겨내고, 미안해하고, 되물은 뒤, 마지막 한마디를 부탁한다.
- 턴마다 보기 3개 + 직접 쓰기를 제공한다. 유형 측정 4턴에서 **6개 유형이 정확히 2번씩** 노출되도록 배치해 특정 유형이 유리하지 않게 한다.
- 위기 상황(자해, 자살 등)은 대본에 넣지 않는다.

| 턴 | 친구 메시지 | 보기 | 수집 |
|---|---|---|---|
| **T0 오프닝** | "자...?" | "안 자. 무슨 일 있어?" / "뭐야 이 시간에 ㅋㅋ" / "나도 못 자고 있었어" | 첫 반응 말투 |
| **T1 번아웃** | "나 요즘 진짜 아무것도 못 하겠어. 집 오면 그냥 누워 있어" | **인정** "너 그동안 진짜 잘 버텼어"<br>**안식** "이번 주말은 그냥 푹 쉬어"<br>**동행** "지금 전화할까? 말 안 해도 돼" | 유형 |
| **T2 자책** | "오늘 회의에서 또 실수했어. 나 왜 이 모양이지" | **수용** "실수 좀 하면 어때. 그래도 넌 너야"<br>**공감** "그래서 오늘 하루 종일 마음이 안 좋았구나"<br>**해결** "어떤 실수였어? 수습 방법 같이 생각해 보자" | 유형 |
| **T3 비교** | "다들 잘 사는 것 같은데 나만 제자리인 것 같아" | **인정** "제자리 아니야. 네가 해온 거 내가 다 봤어"<br>**수용** "제자리면 어때. 난 지금의 너도 좋은데"<br>**해결** "누구 보고 그런 생각 들었어? 인스타부터 좀 쉬자" | 유형 |
| **T4 거절** | "말은 고마운데... 솔직히 잘 와닿지는 않아 ㅎㅎ" | "그치, 말이 쉽지. 미안" / "그럼 그냥 더 말해 봐. 들을게" / "그래도 난 진심이야" | 물러남, 들어줌, 다시 설득 |
| **T5 미안** | "미안, 괜히 이런 얘기 해서. 너도 피곤할 텐데" | **안식** "미안해하지 말고 오늘은 그냥 자"<br>**동행** "난 네 얘기 듣는 거 좋아. 언제든 연락해"<br>**공감** "그 말 꺼내기까지 많이 참았겠다" | 유형 |
| **T6 되묻기** | "근데 넌? 맨날 내 얘기만 했네. 넌 요즘 어때?" | **닫힘** "나야 뭐 괜찮지"<br>**돌림** "내 얘긴 됐고, 넌 더 없어?"<br>**모름** "글쎄... 잘 모르겠어" | 받는 힘 |
| **T7 마지막** | "이제 자야겠다. 고마워. 자기 전에 한마디만 해줄래?" | 직접 쓰기 권장 (막히면 "대신 고르기"로 앞서 보낸 말 중 선택) | 돌려줄 문장 |

T6의 보기에는 "사실 나도 좀 힘들어" 같은 **열림** 선택지를 일부러 넣지 않는다. 쉽게 고를 수 있는 정답처럼 보이면 신호가 흐려지기 때문이다. 자기 얘기를 직접 입력한 사람만 '열림'으로 분류한다. 이 처리가 과한지는 사용자 테스트로 확인한다.

### 친구의 반응

- 직접 쓴 말에는 정확히 맞는 답을 할 수 없으므로, **어떤 말 뒤에 와도 어색하지 않은 반응**을 대본에 넣는다. 예: "...그렇게 말해주는 사람이 너밖에 없다", "ㅎㅎ 잠깐 눈물 날 뻔"
- 보기로 보낸 말에는 유형별 맞춤 반응을 넣는다. 예: 동행형 뒤에 "전화는 괜찮아. 근데 그 말 고맙다"

## 6. 무엇을 수집하고 어떻게 해석하나

| 수집 항목 | 수집 방법 | 결과에서 쓰는 곳 |
|---|---|---|
| 고른 위로 유형 | 턴별 보기 | 주 유형, 부 유형 |
| 내가 직접 쓴 문장 | 입력 텍스트 | 돌려주는 문장, 키워드 분류 |
| 보기를 고쳐 보낸 여부 | 보기 원문과 비교 | "내 말투로 고쳐 보낸 말" |
| 쓰고 지운 횟수 | 전송 전 입력 변화 | "보내기 전에 N번 고쳤어요" |
| 되묻기 횟수 | 물음표, "왜", "어떤" 등 | 먼저 묻는 사람인지 |
| 말투 표지 | ㅠㅠ, ㅋㅋ, ㅎㅎ, 문장 길이 | 대화 습관 |
| T4 대응 | 보기 또는 직접 쓰기 | "위로가 튕겨 나왔을 때" 습관 |
| T6 답 | 보기 또는 직접 쓰기 | 받는 힘 |

쓰고 지운 횟수까지 추적하는 것은 낯설게 느껴질 수 있으므로, 시작 전 안내에 포함하고 수치와 원문 모두 **기기 안에서만** 처리한다. 지운 글의 내용은 저장하지 않고 횟수만 센다.

### 채점 규칙 (초기값)

```text
T1, T2, T3, T5 보기 선택            해당 유형 +1
직접 쓴 문장 (유형 분류됨)           해당 유형 +1.5
T7 마지막 한마디                    해당 유형 +2

주 유형 = 최고점 유형
동점 시 = T7 유형 → 직접 쓴 문장의 유형 → 가장 나중에 고른 유형 순
부 유형 = 그다음 점수 유형
```

### 직접 쓴 문장 분류

1차 버전은 AI 없이 브라우저 안의 키워드 사전으로 분류한다.

| 유형 | 키워드 예시 |
|---|---|
| 인정 | 잘했, 잘하고, 대단, 버텼, 고생했 |
| 안식 | 쉬어, 자, 그만해, 내려놓, 천천히 |
| 수용 | 괜찮아, 그래도 너, 있는 그대로, 어때서 |
| 동행 | 옆에, 같이, 함께, 전화, 언제든 |
| 공감 | 힘들었, 속상, 그랬구나, 마음이 |
| 해결 | 해보자, 방법, 먼저, 정리, 왜 그런지 |

키워드 분류는 정확도에 한계가 있다("괜찮아"만 해도 여러 뜻이다). 그래서 분류가 안 되거나 두 유형이 겹치는 문장은 반전 직전에 사용자에게 한 번 묻는다. 최대 2문장까지만 묻고, 나머지는 점수에서 제외한다.

> "이 말은 어디에 가까웠나요?" (선택 탭 6개)

## 7. 안전과 표현 기준

### 근거의 범위를 정직하게 밝힌다

"남에게 건네는 위로가 내가 듣고 싶은 말"이라는 전제는 **검증된 사실이 아니라 콘텐츠의 가설**이다. 친구에게 그 말이 필요해 보여서 건넸을 수도 있다.

- **쓰지 않는 표현**: 진단, 결핍 판정, "당신은 ~입니다"
- **쓰는 표현**: "~일지도 몰라요", "이 말이 오늘 당신에게도 필요했을 수 있어요"
- "내면 아이"는 대중 심리 표현이다. 비유로만 쓰고 측정 결과처럼 표현하지 않는다.
- "다른 말에 더 끌려요" 버튼으로 결과를 사용자가 고칠 수 있게 하고, 이 반응을 가설 점검 지표로 쓴다.

### 원안 참고 자료에 대한 주의

- IRI(Davis, 1980), SCS(Neff, 2003), DSQ(Bond 외, 1983)는 **이론적 참고**로만 쓴다. 문항을 옮기거나 "SCS 기반 진단"이라고 쓰지 않는다. 세 척도 모두 자기보고식 연구 도구이며 단독 진단 도구가 아니다.
- 원안의 "임상에서 이 척도들을 조합해 진단한다"는 설명은 근거를 확인하지 못했으므로 사이트 문구에 쓰지 않는다.
- "투사적 공감", "역방향 위로"는 표준 진단명이나 정립된 학술 용어로 쓰지 않는다. 필요하면 "이 사이트에서 부르는 말"로 표기한다.
- 출시 전 상담·임상심리 전문가에게 결과 문구 검수를 받는다.

### 위기 신호 대응

직접 쓴 문장에 "죽고 싶", "자살", "자해", "사라지고 싶" 같은 표현이 있으면:

1. 대화를 잠시 멈추고 안내 화면을 띄운다. "혹시 지금 힘든 건 당신 쪽인가요?"
2. 도움받을 곳을 보여준다: 자살예방 상담전화 **109**, 정신건강 위기상담 **1577-0199** (출시 전 번호 재확인)
3. [대화 이어가기]를 함께 두어 강요하지 않는다.

결과 하단에는 항상 "마음이 오래 무겁다면 전문가와 이야기해 보세요" 안내와 위 연락처를 둔다.

### 프라이버시

- 1차 버전은 **서버 전송 없음**. 대화와 이름은 메모리와 `localStorage`에만 두고, 결과 화면에 [내 대화 지우기]를 제공한다.
- 공유 링크에는 유형 코드만 넣는다. 예: `?t=rest`
- 공유 카드에 내 문장을 넣는 것은 **기본 해제**. 기본 카드는 유형별 문구를 쓰고, 사용자가 켜야 내 문장이 들어간다. 친구 이름은 넣지 않는다.
- 공유 전 미리보기를 보여준다.

## 8. 디자인 방향

- **분위기**: 새벽 2시의 방. 어두운 네이비 배경 + 따뜻한 스탠드 조명 톤. 라이트 모드 없이 시작해도 된다.
- **메신저 표현**: 특정 메신저 앱의 색, 아이콘, UI를 따라 하지 않고 일반적인 말풍선 형식만 쓴다.
- **반전 연출**: 배경이 차가운 네이비에서 따뜻한 앰버로 서서히 바뀐다. 유형별 색도 이 온도 범위 안에서 정한다.
- **결과 카드**: 큰 문장 하나 중심. 인스타그램 스토리 비율(1080×1920)과 정사각형(1080×1080) 제공.
- **접근성**: 새 메시지 `aria-live` 낭독, 키보드 전송, 터치 영역 44px 이상, 대비 WCAG AA.

## 9. 기술 구성

기존 인지 왜곡 테스트와 같은 **무서버 정적 사이트**(HTML, CSS, Vanilla JS)로 만든다.

```text
/
├─ index.html          # 랜딩 + 대화 + 결과 (단일 페이지)
├─ assets/
│  ├─ css/style.css
│  └─ js/
│     ├─ script.js     # 대화 스크립트, 유형, 결과 문구 (모든 텍스트)
│     ├─ scoring.js    # 채점, 키워드 분류, 말투 신호, 위기 표현 감지 (순수 함수)
│     ├─ chat.js       # 대화 진행, 입력 추적, 연출
│     ├─ result.js     # 반전 연출, 결과 렌더링
│     └─ card.js       # Canvas로 공유 카드 PNG 생성
└─ tests/scoring.test.js
```

- 문구는 `script.js` 한 곳에서 관리한다.
- 채점과 분류는 순수 함수로 분리해 `node`로 테스트한다. 특히 동점 처리, 분류 실패, 건너뛰기를 검증한다.
- 공유는 Web Share API를 우선 쓰고, 안 되면 이미지 저장과 링크 복사로 대체한다.
- `localStorage` 접근은 try/catch로 감싸고, 저장이 안 돼도 끝까지 진행되게 한다.

## 10. 단계별 범위

### 1단계: 프로토타입
- 대본과 결과 문구 완성
- 대화 화면 + 채점 + 텍스트 결과까지 구현 (연출과 카드 제외)
- 5~10명 사용자 테스트: "진짜 친구처럼 답했는가", "결과가 찔렸는가"를 확인

### 2단계: MVP 출시
- 말풍선 반전, 결과 화면, 공유 카드
- 위기 대응, 전문가 문구 검수, 개인정보 안내
- 정적 호스팅에 배포

### 3단계: 확장 (반응을 본 뒤 판단)
- **상황 팩**: 이별, 취업 실패, 가족 갈등 등 대본 추가
- **친구 비교**: 링크를 보내 친구의 유형과 비교. "내가 건넨 말 vs 네가 듣고 싶은 말"
- **AI 대화 모드**: 8턴 자유 대화와 문장 분석. 대화가 훨씬 자연스러워지지만 서버, API 비용, 입력 내용 외부 전송 고지, AI 답변 안전장치가 필요하므로 1, 2단계 지표를 확인한 뒤 결정
- **익명 통계**: 동의한 사용자의 유형 코드만 집계. 문장 원문 수집은 민감정보 이슈가 있어 법률 검토 없이는 하지 않음

## 11. 위험과 대응

| 위험 | 대응 |
|---|---|

| 진단으로 오해 | 첫 화면과 결과에 고지, "진단" 표현 금지 |
